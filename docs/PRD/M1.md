# Zippy Logistics — Milestone M1: Supabase Schema, RLS, Seed & Types

## Objective
Implement the complete PRD v2 PostgreSQL schema in Supabase, including extensions, tables, relationships, deterministic triggers, views, Row-Level Security (RLS) policies, seed data, and generated TypeScript types.

## Entry Criteria
- M0 repository skeleton is in place.
- `.env` copied from `.env.example` with valid Supabase/local DB credentials.
- Docker Compose `db` service can start.

## Core Tables Covered
- `users` — unified identity with `base_role`/`active_role`/`payment_hold`.
- `customer_profiles`, `driver_profiles`, `transport_companies`
- `vehicles`, `vehicle_telemetry`
- `orders` — full order lifecycle, pricing, commission/service-fee fields.
- `payments`, `payment_transactions`
- `admin_actions`, `driver_alerts`
- `ai_agent_activities`, `ai_agent_interventions`
- `notification_log`, `webhook_events`

## Key Constraints & Business Rules
- Order state machine enforced by `transition_order` SECURITY DEFINER function.
- Commission/service fee calculated automatically by trigger:
  - Driver providers: 10% commission.
  - Transport-company providers: flat ₹700 service fee.
- Long-halt driver alert created by telemetry trigger (> 30 min stationary).
- Payment transactions recorded automatically on payment status change.

## RLS Policy Principles
- Users can read/update only their own `users` row.
- Customers see only their own orders and profiles.
- Drivers see only their own profile, assigned orders, and telemetry.
- Transport companies see their own company and assigned orders.
- Admins have full read access.
- Telemetry INSERT is open to authenticated service accounts; SELECT is driver-scoped.

## Human Gates
None for M1. All schema decisions are deterministic from PRD v2.

## Rollback
Drop and recreate `public` schema, or restore from pre-M1 dump.

## Risks
| Risk | Mitigation |
|---|---|
| PostGIS/pgvector extension availability | Dockerfile installs both; migration runs `CREATE EXTENSION IF NOT EXISTS`. |
| Large seed file | Split seed into data categories; keep under 5 MB. |
| Type drift | Types are hand-maintained in M1; M2+ will automate via `supabase gen types`. |
